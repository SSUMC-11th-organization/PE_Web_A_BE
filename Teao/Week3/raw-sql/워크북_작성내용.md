# 워크북 작성 내용

## 이번 실습 목표

MySQL Workbench에서 직접 실행하던 SQL을 NestJS 서버의 Repository에서 실행한다. Controller, Service, Repository를 분리하고 `mysql2` 커넥션 풀을 사용한다.

## 구현 결과

- `GET /books`: `book` 테이블 전체 조회
- `POST /books`: 파라미터 바인딩으로 도서 등록
- `GET /books/category/:categoryId`: 카테고리별 도서 조회
- `POST /rentals`: 현재 시간과 7일 뒤 반납 예정일을 포함한 대여 기록 생성
- DB 연결 정보는 `.env`에서 읽고, 커넥션 풀은 `database.provider.ts`에서 생성
- 흐름: `Controller → Service → Repository → MySQL`

## 실행 확인

1. `library_week1` 데이터베이스를 준비한다.
2. `npm install` 후 `.env`를 작성하고 `npm run start:dev`를 실행한다.
3. Postman에서 `GET http://localhost:3000/books`를 호출해 기존 도서 목록을 확인한다.
4. 아래 JSON으로 `POST http://localhost:3000/books`를 호출한다.

```json
{
  "categoryId": 1,
  "title": "클린 코드",
  "description": "애자일 소프트웨어 장인 정신",
  "author": "로버트 C. 마틴"
}
```

5. 성공 문구를 확인한 뒤 `GET /books`를 다시 호출해 새 도서가 추가됐는지 확인한다.
6. `GET /books/category/1`로 특정 카테고리 도서만 조회한다.
7. `POST /rentals`에 `{"userId":1,"bookId":1}`을 보내 대여 기록 생성 결과를 확인한다.

## 느낀 점

Raw SQL 방식은 DB 컬럼명과 파라미터 순서를 직접 관리해야 해서 오타와 타입 오류를 실행 시점에 발견할 수 있다. 다음 주차에는 DTO와 ORM을 사용해 이런 수동 매핑을 줄일 수 있을 것으로 예상한다.
